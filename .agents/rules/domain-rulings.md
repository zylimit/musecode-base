# 领域口径库规则（canon）

> 来源：`cc-base/.claude/rules/domain-rulings.md`（整件蒸馏，路径适配本仓）。
> 本文件是口径的唯一裁判：七栏、四类分拣、三种变更、四种老化、入库两问、三类依据一律以此为准，skill 不复述。
> 载体：项目根 `domain/`（与 REQ 同级，不进 `.agents/`）；不存在不报错、不催补。

## 定位与边界

- 口径 = 这个领域里"事情是怎么算的"：跟领域走，不跟仓库/人不跟项目走。换库换人仍成立才是口径。
- 副产品，不是流程环节：不进任何验收链；存在的理由只有一个——让 AI 下次输出更准。
- 与三样划界：`progress.md` Decisions（项目决策，跟项目走）、`.agents/feedback/`（AI 方法纠正，跟 AI 走）、REQ 功能需求（产品要做什么）。口径是第四种。
- 入库两问（按序）：① 下次哪一步会因为它不一样（答不出不收，哪怕是真的）；② 本次做完后还成立、还需被下一个人读到吗。两问都过才收。
- 条目形态：ID + 一句话标题；按域分文件（`domain/<域>.md`），域取自领域本身；一时归不进的进 `domain/_未归域.md`。

## 七栏

- **现行值**：判据式写法（"关联键＝OLT IP，禁止用名"），不写叙述式（叙述式留补全空间=留幻觉空间）。
- **依据**：只认三类——① 实测撞出来的（数/表结构/跑不通的实验）；② AI 查外网（协议/厂商文档/标准）；③ 人查公司内部。凭记忆/推断说得再确定也不收。分工固定：AI 去外网，人去内部；一条口径常要两类才立得住。
- **适用范围**：哪些查询/页面/导出生效；无范围会被误用。
- **取代**：顶掉哪条旧口径，旧条标记不删（AI 会检索到旧措辞，删了只剩幻觉）。
- **失效条件**：什么发生后不再成立（多从依据倒推）。
- **被谁依赖**：哪些口径/指标/导出引用本条；改它连带复核（准不准决定关联失效跑不跑得起来）。
- **已知污染**：口径对、数据暂不满足前提（修复后自动恢复）。一条只写一个判据，两个就拆两条。

## 四类分拣 / 三种变更 / 四种老化

- 分拣：口径（做完仍真→进库）/ 范围限制（约束本次→不进）/ 事实记录（有时效→挂"已知污染"）/ 待拆（两类混写→拆开，混合是容器逼出来的，不怪写的人）。
- 变更：修订（值变，同一条的新版，不另立）/ 取代（旧条标记不删）/ 收窄放宽（范围变，最易漏记）。修订史进 git，只有取代关系显式写（AI 读不到 git log）。
- 老化：条件失效（作废）/ 关联失效（被依赖变了→依赖方全进待复核，最重要最易漏）/ 批量失效（模块下线）/ 污染（≠失效，混了会有人去改正确的口径）。

## 采集与读取

- 采集寄生在已有动作上：子智能体回执的 Domain findings 栏（顺手填，填不出写 None；不催，催出来的是凑数）。
- 线索≠口径：子智能体撞出来的是线索（现象真、解释未必真），凑齐依据才定论；定论归主 Agent 和用户。
- 收到三类分去向：领域口径→`domain/`；框架实践问题→feedback/当场改；需求存疑→回流 product-spec-builder。判据：换个八竿子打不着的项目还成立吗。
- 检索用结构化（域/技术对象/状态），不用向量（字面像语义无关会被拉一起=幻觉源）。
- 读取时机（任务级）：派单时（进 Business Context，最主要）/ 审查时（判据另一半）/ 需求迭代前 / 调试定预期时。不挂 recap、不挂 SessionStart、不挂对话开头。
- 明确不做：定期复查、知识图谱、向量库、从 CHANGELOG 自动抽取。
