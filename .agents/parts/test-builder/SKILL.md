# test-builder

- 版本：1.0.0
- 适用：新模块测试基建、Phase 回归套件、发版验收测试。不适用：单条红锁（dev-builder/bug-fixer 内建）。
- 输入：REQ 验收条目 + DFX 目标 + 现有测试结构。
- 输出：测试文件 + 运行报告（pass/fail 计数）+ 未覆盖清单。

## 步骤

1. 定策略：按风险分级选防线——P0（越权/数据损坏/不可逆副作用/恢复承诺）先验真正承担保护的边界；P1（受影响行为/契约/常见失败）；P2（长尾，按价值成本排，不自动豁免）。成功判据与 DFX 目标逐条映射到最便宜的有效层；低层证不了真实入口/隔离/恢复时保留必要集成/E2E。
2. 补基建：runner/固件/隔离（测试数据与生产隔离、可重复、可重置）；CI 可跑，无人工前置步骤。
3. 写用例：happy path + 边界 + 负例 + 并发/时序（如适用）；断言来自需求原文，不复述实现逻辑。双向转换/外部格式先立**单向预期**再判往返（`2500mm→2.5m` 与 `2.5m→2500mm` 是两条期望，往返走通可能是两端错误抵消）；fixture 不得出自待测函数；足够条件=接受正常行为 + 拒绝目标错误 + expected 有独立来源。
4. 跑通：跑触及面 + 受影响回归（整文件/包，不裁剪），贴真实输出（passed/failed 计数）；红的按代码错/测试错分流（bug-fixer 修代码 / 本 skill 修测试），不改断言迁就错误。全量只在发布闸或契约要求时跑，不当日常默认。
5. 覆盖评审：触及面逐文件确认；高风险路径（支付/权限/迁移）必须有点对点用例；覆盖率数字仅参考，不为数字凑用例。
6. 接门禁：测试命令进 `verify.sh` 探测链或 CI；回归套件命名稳定，可被 branch-finisher/release-builder 复用为前置闸。
7. 报告：新增/修改文件、运行输出、未覆盖项与原因（注明是"不测"还是"测不了"，后者进风险）。老化纪律：需求/契约/实现变了、flaky、变慢即复核相关用例；默认每月只看脆弱/昂贵/无主项；长期绿不是删保护测试的理由，退役须证原规则已撤销或有有效替代。

## 约束与红线

- 测试发现的是信号不是噪音：失败测试即需求（`ARCHITECTURE.md` 红线 3）。
- 禁止测试替身反向依赖产物脚本；禁止生产数据进测试库（PRI）。
- 不写"永远绿"的断言（`assert True`、无断言的冒烟）。

## 验收

- 运行器真实输出全绿；每条 REQ 验收条目有对应测试或显式"不测"声明。
- 同一命令在 CI 与本地结果一致（无环境相关 flakes，或 flakes 已隔离标记）。

## 示例

为派单核心流建回归：`tests/dispatch/test_flow.py`（建单→派单→接单）+ `test_edges.py`（空单/重复派/并发抢单）→ `pytest -q` 12 passed → 接入 verify。
