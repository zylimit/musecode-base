# 风险分级、比例与用例老化

规划测试、核对测试代码预算或维护已有套件时读取。沿用当前 runner、目录、命名/标签和计划；不建立新测试平台、全局注册表或比例硬闸。范围、独立性、required checks 和证据绑定仍由 resolver/plan 决定。

## 按风险选择有效防线

先说明错误的业务后果、发生机会、改动传播和已有防线；无需伪造数字评分。每个用例能否拒绝目标错误，比数量和常年绿色更重要。

| 级别 | 所防风险 | 选择依据 |
|---|---|---|
| P0 | 关键高后果：越权、数据损坏、不可逆副作用、核心结果或恢复承诺失效 | 先验证真正承担保护的边界；发生机会低也不能抹去高后果。 |
| P1 | 本次受影响的主要行为、契约及常见失败路径 | 覆盖用户承诺和改动传播，用区分性输入识别回归。 |
| P2 | 低后果长尾、边缘组合或辅助行为 | 按实际价值与成本安排；不是自动 SKIPPED/DEFERRED 的标签。 |

风险、层次与耗时分别记录：一个昂贵的恢复 E2E 可以是 P0，一个很快的格式断言也可能是 P2。优先选择能识别该风险的最便宜有效层次；低层无法证明真实入口、隔离或恢复时，保留必要集成/E2E。只在 controls 与 plan 允许范围内选集，不让标签更改 Assurance 或 required 检查。

## 可选的代码规模维护

只有项目已有明确目标且当前任务包含规模维护时使用本节；普通实现与验证不因此新增统计步骤或比例目标。沿用既有口径，例如 `R=T/P` 中 T 是测试代码行数、P 是生产代码行数；来源未明确就报告口径未知，不替用户选择目标或为达标换分母。

- 统计项目或可独立交付组件的总存量，不要求每个函数、文件或 diff 达到比例。
- 文档、生成物、依赖和静态数据不进入 T/P；测试 runner/reporter、helper、fixture 中的可执行代码计入 T，不因它们放在 scripts/Skill 目录就改算 P。P=0 标明不适用，不凑比例。
- 同次报告说明统计范围、计数版本、逐文件分类/排除与内容摘要；同时列 T/P 和 T/(T+P)，但后者不改变已采用分母。有效物理行统计的字符串/注释识别边界如实说明，不能冒充 AST 语义行或精确 SLOC。未测量不得声称合规，数值越界如实记录，与测试 PASS/FAIL 分开。
- 与项目既有目标的偏差只用于发现真实风险缺口、重复 setup/断言和更低成本的等效覆盖。不能仅为比例增删用例，也不能用格式压缩、改范围、生产代码灌水或删除关键断言刷比例。
- 有效保护确有必要时，在现有计划/报告说明风险覆盖、独特断言、执行成本与复核条件；不另造百分比容差、台账或审批流程。比例不证明正确性，不取消 required 检查、不清除实际 FAIL，也不作为本次交付完成标准。

## 事件触发老化，少量定期复核

在已有测试目录、套件说明或计划中按套件继承 owner、风险/契约、执行层次与适用范围，不要求每条用例填表。只有例外、异常或发生变更的条目，补最近复核结论和下次触发条件/日期。

需求/契约/实现变化、重复断言、新替代覆盖、flaky 或明显变慢时，复核相关用例。默认每月只看脆弱、昂贵或无主项，不全量逐例重审。利用现有 runner 的耗时/失败输出，先处理重复初始化、无效等待和重复路径；并行化只有隔离与依赖允许时采用，不能用固定 sleep、扩大超时或 retry-to-green 隐藏失败。

有运行观察时按完整用例身份和源码版本区分样本，保留执行状态、耗时与未运行范围；同名截断、旧源码结果或缺失记录不能拼成当前连续绿灯。沿实际 runner 判断过滤、跳过、动态子例和执行完成性：预览只知道注册项时，不能报子例已覆盖。失败、跳过、陈旧和无样本分别提示，观察仅支持排查/复核建议，不是质量 receipt，也不自动变更级别或退役用例。

每次复核只作必要判断：预期来源还有效吗，断言能识别目标错误吗，存在更便宜且等效的覆盖吗？按证据保留、更新、合并或退役；长期绿色或年久不是删除保护测试的依据。退役必须证明原规则已撤销或已有有效替代覆盖，保留依据与替代位置。

隔离仅用于明确非 required 的诊断项，须有 owner、原因、期限与替代证据；到期复核，不无限延期。产品 FAIL 不能借隔离消失，required/保护检查不能因此豁免，未执行不能写 PASS。

## 执行到证据足够即停

先做受影响的快速反馈；冻结最终实现、相关文档与 manifest 后，必要完整 gate 默认执行一次。命令输出、退出码与 receipt，或 runtime 校验仍适用的执行事实，交主 Agent 消费；不因交接再跑一遍。只有变化、失败、证据疑点或用户明确要求才追加相应验证；不同 subject/plan/policy 重新验收，旧 PASS 不直接搬到新绑定。

无行为变化、无真实覆盖缺口的文案小改不新增测试；现有 controls/plan 要求的检查照常执行。新用例须说明所防风险和独立预期，能接受正常行为并拒绝错误即可，不为覆盖数字或维持比例穷举组合。
