# domain-rulings

- 版本：1.0.0
- 适用：领域口径的分诊/查询/收录。口径回答"怎么算"，不回答"要做什么"；是副产品，不进任何验收链。
- 输入：一段领域知识 / 查询（域或技术对象）/ 收录请求。
- 输出：分诊结论（四格落定+去处）/ 现行值 / 待复核清单 / 依赖链 / 收录回执。

## 步骤

1. 认动作：记一条→收录；问按什么算→查现行值；问还算数吗→列待复核；问牵动谁→看依赖；只讲事没说记→先分诊。认不出问一句，不猜。
2. 四象限分诊（问"这条当初是谁知道的"，一问一答，不先给推荐答案）：人知AI不知→Spec 规则与例外；AI知人不知→架构/ADR/Decisions；双方都知→功能需求；**双方都不知、共同查证得出→口径库（唯一入口）**。
3. 入库两问：① 下次哪一步会因为它不一样（答不出不收）；② 离开本项目还成立吗。两问都过才往下走。
4. 补齐七栏：现行值（判据式写法）/依据（三类：实测撞出/AI 查外网/人查内部，缺类就停，把"谁去查哪类"交回给人）/适用范围/取代/失效条件/被谁依赖/已知污染；一句两判据拆两条。
5. 写入：transient 由本 skill 直写 `domain/<域>.md`（按域分文件，域取自领域本身）；查现行值/列待复核/看依赖只读。修订只改值不另立条；取代旧条标记不删（AI 会检索到旧措辞）。
6. 老化：条件失效作废；被依赖条目变了→依赖方全进待复核；污染（口径对数据不对）≠失效，不混。不做定期复查、不做向量检索（按域/技术对象/状态三维查）。
7. 交接：现行值进派单包 Business Context；第一格条目回指 product-spec-builder；分诊取舍记 `progress.md` Decisions；库内修订靠 git log，不记 progress。

## 约束与红线

- 分诊在收录之前；跳过分诊直接收的，库必成杂物间。
- 凭记忆/推断的"依据"说得再确定也不收；凑出来的依据不如悬着。
- 检索不用向量：字面像语义无关的会被拉到一起，那是幻觉来源。

## 验收

- 查询类：回了现行值+范围+失效条件，被取代/污染状态一并点明。
- 收录类：七栏齐、依据齐、ID 可定位；诊清楚了就算办完，不追"库里多少条"。

## 示例

用户："记一条，OLT 关联必须用 IP。"→问当初谁知道→"一直这么办"→第一格→回指 Spec 规则与例外，口径库不收（并说明为什么）。
