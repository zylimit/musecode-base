# 实际产物、加载入口与失败恢复

显式交付涉及打包、安装、加载或远端状态变化时读取。只跟踪本次真实存在且获授权的环节；普通本地文件产出不增加部署流程。命令、渠道与宿主行为以当前项目入口和必要的官方核验为准，不固化供体安装器或缓存规则。

## 执行前读实际入口

从计划执行的脚本、包管理命令或发布工作流向下追必要调用，核对生命周期脚本和默认参数：它会不会安装依赖、访问网络、上传、覆盖已有目录、改登记、启动/停止进程或迁移数据？同名 build/install/package 可能包含不同动作；工具存在不构成动作授权。

已有授权覆盖的本地准备继续做。若命令混入未授权副作用，选择项目支持且能达到当前目标的有边界入口；无法分离时交主 Agent 说明具体动作与必要性，只暂停依赖它的执行。不要为尚未涉及的安装或发布提前加入确认流程。

## 追查用户实际使用的是哪个对象

| 适用环节 | 要取得的关系与观察 | 不能据此推定 |
|---|---|---|
| 源树/构建 | 本次源标识、工作区范围、配置及实际输出 | 输出目录存在就一定是本次生成；源改了，旧 zip 也改了。 |
| 最终包 | 最终路径和 digest，实际成员集合、关键入口/资源、版本与受控内容规则 | 清单合法就代表归档内容完整；构建通过就代表过滤后的包仍可用。 |
| 登记/安装副本 | 实际复制或链接关系、解析后的目标、过滤/改写步骤、登记指向与副本内容 | 列表有名字就代表使用此次来源；源树哈希直接代表改写后的副本。 |
| 加载实例 | 本次进程/会话实际使用的来源与版本，真实用户入口和必要业务观察 | 登记成功就代表旧会话已重载；本地模拟入口就代表真实宿主已验证。 |

必要文件从实际引用和确认功能反推：例如某入口读取资源，就核对该资源经过打包/安装过滤后仍存在、可达且属于本次版本。可以在已授权的隔离解包目录检查，避免运行时从源工作区偶然补到文件；这只证明隔离环境中实际走过的路径。

过滤、重写 manifest、签名或另拷文件改变对象后，重新记录相应身份和关系；按现有清单与工具核验最终集合，不新增一套自造 provenance 权威。修正清单后必须重新生成受影响产物，再审计新产物。旧 staging 与新 zip、或新 staging 与旧 zip 都可能同时存在，不能按文件名或存在性猜哪份可交付。

若本次只授权 package，就核验 package 的必要结果，并在交接中说明安装/真实加载未验证；不能擅自安装来填满表格，也不能把缺少必要质量证据改名为通过。需要交付到多个目标时，各目标按其要求提供适用证据，不借另一目标替代。

## 失败以后，先查发生到哪里

失败可能发生在前检、复制后、登记后或提交远端后。先保留实际结果，再逐项确定：哪些动作确认没发生，哪些已有可读事实证明完成，哪些结果仍未知。这是工作说明，不新增 runtime 状态。

- 确认尚未产生副作用：修正前提后，可在原授权范围内重试相应步骤。
- 已完成一部分：核对剩余动作依赖、用户定制和数据状态，再决定继续、补偿或恢复。不要把“后一步失败”写成“前面全没发生”，也不要把局部成功写成总体完成。
- 连接中断、超时或响应不明：按渠道可用的查询接口核对目标版本、对象或请求归属；无法确定时保留未知。查询和恢复网络不自动授权重复创建、覆盖或删除。

不要原样重跑整套安装/发布脚本去碰运气。重试是否安全取决于当前状态、实际幂等语义和原授权，不能仅由上次退出非零判断。

## 回退与前向修复各自需要依据

会改变既有环境时，执行前承接项目的恢复方案：可用旧产物/数据基线、兼容条件、触发点、负责者和授权范围。失败后按实际方案恢复并验收；回滚命令成功仍需确认目标状态及关键业务可用。

已迁移且不能逆转的数据、已分发到用户端的程序或渠道不允许复用的版本，可能只能前向修复。撤下页面、删除 release 或卸载程序不能让所有用户和数据自动回到旧状态。实际动作时核对现行渠道规则，不用固定小时数或通用“撤包即可恢复”作承诺。

交接用既有字段写明：交付到哪一环，真实对象/目标，仍受影响的用户或数据，恢复或前向修复结果，未验证项与下一负责者。需要业务例子时读 [字幕草稿案例](../../dev-builder/references/async-proofreading-case.md) 的交付场景；它的授权仅属于虚构例，不能据此执行目标项目的安装或发布。
