# bug-fixer

- 版本：1.0.0
- 适用：已确认的现象级缺陷。不适用：需求不明（先回 product-spec-builder）、性能优化（先定 DFX 口径）。
- 输入：缺陷现象（原话/截图/日志/失败测试）+ 预期依据（Spec 条目/案例）。
- 输出：根因 + 最小修复 + 防回归测试 + 修复报告。

## 步骤

1. 保护现场：`git status/diff` 区分用户已有修改与本次缺陷；记录环境（版本/分支/数据）。
2. 稳定复现：从具体事件还原参与者/输入/时间/操作顺序，跑最小复现命令，保存输出与退出码；无法复现则列已排除条件与仍缺什么，不猜修。
3. 圈定影响：追调用链、状态边界、公共契约；大仓用 catalog 影响闭包，不做无界扫描。
4. 验证假设：先找可比的正常路径，沿边界定位**第一次可观察分歧**（分歧处≠根因，继续核对上游）；列表格写清候选/支持/反驳条件/最小区分实验/实际观察，一次只变一个条件；阴性结果同样更新判断，没触达故障路径的实验不算通过。"代码偏离规则"与"规则本身歧义"分开——后者带来源冲突回流需求，不伪造根因。
5. 红测锁定：动手前先有一条此刻必然变红的测试（或可重复人工复现），确认红在预期原因上；修复中禁止削弱其断言。
6. 最小修复 + 回归：修根因；重跑红锁（绿）→ 重跑原始复现 → 跑触及面测试 + `verify.sh`；补防回归测试。
7. 三次熔断：同一根因连续三次修不好，停手返回（已验证假设与反证/最小复现/缺失信息/建议升级项），不盲试第四次。

## 约束与红线

- 重启/清缓存/扩大 timeout/吞异常不是根因修复（`ARCHITECTURE.md` 红线：修根因）。
- 终止进程须用户明确授权且只针对确认属于本项目的 PID；禁模糊进程名全局清理（SAF）。
- 修复不改 fixture/expected 迁就错误；不凭当前实现反推"正确答案"。

## 验收

- 原始缺陷不再出现；红锁变绿；既有行为无回归；证据绑定当前 diff。
- 报告含：根因、修复 diff、回归证据、未测范围；修正了业务理解的，指出需回填的 Spec/计划来源。

## 示例

"退款后还显示完成"：先核"完成"的两种含义（履约结束 vs 账务结清）→ 查 Spec 依据 → 复现（退款单状态流）→ 红锁定"已履约退款未到账应显示 X" → 修状态机 → 回归。
