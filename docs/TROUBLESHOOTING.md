# 故障排查（TROUBLESHOOTING）

> 来源：cc `docs/guide/05/06/07/08/10/12/13/14` 各章"常见坑"表（合并适配）+ 本仓门禁 §8 原有条目。

## 门禁与脚本

| 现象 | 处理 |
|---|---|
| `smoke.sh` 报文件缺失 | 按输出补文件，不要改脚本跳过检查 |
| git 钩子未触发 | `install-githooks.sh status` 查 `core.hooksPath`；被占用（husky）则手动合并 |
| 想 `--no-verify` 跳过 | 禁止。误报修门禁并留 ADR，而非跳过 |
| 原生 hook 改了不生效 | 改配置后必须**开新会话**；畸形文件只告警且该源零 handler |
| `arch-check --gate` 无基线 | 先 `--record` 立基线并提交；老仓带债接入同理 |
| `tsc` 报找不到模块 | 先确认依赖装了（`node_modules` 缺席是 BLOCKED 不是 FAIL） |
| verify 里 node 堆栈刷屏 | 看过滤后的前 15 行（`at /node:internal` 已滤掉），全文在 `/tmp/verify_*.log` |
| predev-lint 报段缺失 | 对照模板补段；小 REQ 允许缺可选段（AI 使用说明/技术方向/决策依据/澄清记录/回归/变更记录） |
| plan-lint 报"需求没人做" | Task 行引用对应 FR 编号，或确认该需求本期不做（改范围） |
| fitness 误报规则内容 | 规则定义行加抑制标记（`rule reason="..."` 语法），不要删规则 |
| skill-lint 报 description | 描述必须"当/由"开头（触发条件优先），≤180 字；目录名=frontmatter name |

## 需求与设计

| 现象 | 处理 |
|---|---|
| 用户说"都要" | 逼单选："只能保一个保哪个"；冲突进决策依据，不自己圆 |
| 听到"一般/通常/应该" | 标 `[推断]` 并要具体例子 |
| 待定清不掉 | 每条必须有"谁能答/押后到/不答先按什么做"，否则不许开工 |
| 复述被挑错 | 改对应条目并回"改了第 X 条"，不整篇重写 |
| 设计稿与 Brief 对不上 | 先查 Brief 追 office：行为改 Brief，视觉改 DESIGN，两份一起改 |
| 形容词进 Spec（"简洁高级"） | 翻成可观察属性 + 要参照，翻完 recap 确认 |

## 开发与测试

| 现象 | 处理 |
|---|---|
| 同一测试本地绿 CI 红 | 查 CI 日志全文（`gh run view --log`），环境差异进测试隔离 |
| flaky 测试 | 先隔离标记再修，不删不断言；test-age 退休只看"跑够且从没红" |
| 修了三次还不好 | 熔断停手：交假设/反证/复现/缺口，不盲试第四次 |
| 新文件"已创建"但找不到 | 用 `wc -l` + 锚点 + `git status ??` 三重证明，不只看 diff |
| 改了 fixture 就绿 | 停：先判代码错/测试错/Spec 错，Spec 错则 skip 注明+需求存疑 |
| 并行写冲突 | 检查 owned paths 是否 disjoint；重叠的串行 + 指定 integration owner |

## 发布与收尾

| 现象 | 处理 |
|---|---|
| 构建卡住（CPU 0% 且时长涨） | 先诊断死锁/等输入，不盲等；配置声明≠实际，先验实际布局 |
| 产物扫出密钥 | 立刻停：删密钥、轮换、查历史；修完重建再审计 |
| dev 测通但安装包不行 | 安装测试必须从安装包测，不从构建输出目录测 |
| 部署显示 Up 很久 | 不看 Up 时长，看容器创建时间+镜像 tag+健康端点+live 冒烟 |
| 发布命令超时/断线 | 视为"可能已执行"：先查目标实况，再定重试或回退 |
| 收尾分支删不掉 | 确认已合并（`-d` 拒绝即信号）；PR 待合并的分支不删 |

## 记忆与进化

| 现象 | 处理 |
|---|---|
| 压缩后 AI 失忆 | 跑 `session-recap.sh` 回注（Pinned/现存 Decisions/待办/断点，60 行预算） |
| 同一纠正反复出现 | 查 feedback 是否 pending：pending 表示还没生效，催落地 |
| 进化提议太多 | 逐条确认/跳过；跳过标 skipped 不再提；无实证的不毕业 |
| progress.md 胀大 | Notes+Done>100 或 Decisions>30 即归档；Pinned 封顶 15 |
