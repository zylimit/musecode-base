## 开发规则

- 每 Phase 完成走门禁链：`smoke.sh` → `verify.sh` → `check.sh`（+ `arch-check.sh`，如有 catalog）
- 门禁全过 + 验收证据贴出才算 Phase 完成
- Commit message 格式：`phase-N: 简要描述`
- 纠正传播：下游纠正先定位本计划哪条 Task/验收受影响，同步后下游重验，不只改 Spec 不动计划
- Phase 顺序：核心价值流程（含最小骨架）→ 验证核心假设 → 重要功能 → 辅助功能 → 收尾；依赖只做校正，不做主轴
- Task 描述里写上关联的 REQ/FR 编号，便于双向追溯
