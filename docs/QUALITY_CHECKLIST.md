# 质量 Checklist（五维）

> 用法：每个交付按节打勾；阻断项（🔴）任一不满足即不许合入。证据列填“测试路径 / 命令输出 / ADR 编号”，不写“已自查”一类空话。与 `AGENTS.md` §3–§5、`ARCHITECTURE.md` 红线配套使用。

## 0. 通用证据要求

- [ ] 触及面测试整文件通过（命令 + 输出已贴）。
- [ ] `bash scripts/smoke.sh` 退出码 0。
- [ ] 架构例外已声明或明确“无例外”。

---

## 1. Resilience（弹性/韧性）

目标：依赖故障、超时、重试风暴下系统不雪崩，且显式表达降级态（`ARCHITECTURE.md` 红线 4，`HARNESS.md` H7）。

| 编号 | 检查点 | 通过标准 | 阻断 |
|---|---|---|---|
| RES-1 | 外部依赖（网络/模型/API）不可达 | 返回显式降级输出（状态字段/错误文案），禁止空列表/零值伪装健康 | 🔴 |
| RES-2 | 超时 | 每次外部调用都有超时（默认 ≤ 30s，需长任务则 ADR 说明） | 🔴 |
| RES-3 | 重试 | 有界重试（≤ 3 次）+ 指数退避 + 抖动；非幂等操作不自动重试 | |
| RES-4 | 熔断/限流 | 高频调用有熔断或限流；熔断打开时走降级分支且可观测 | |
| RES-5 | 幂等 | 重试/重放同一请求不产生重复副作用（有幂等键或去重证据） | |
| RES-6 | 资源上限 | 并发/内存/磁盘/子进程数有上限，超限时拒绝并报错而非 OOM | 🔴 |

常见失败：`except…: pass` 吞错、无超时挂死、失败返回 `[]` 被上游当“无数据”。

---

## 2. Security（安全）

目标：默认安全；输入不可信；密钥不落地；高危操作可审计（`AGENTS.md` §5，`HARNESS.md` H2）。

| 编号 | 检查点 | 通过标准 | 阻断 |
|---|---|---|---|
| SEC-1 | 命令注入 | shell 调用无字符串拼接；用户输入进 argv/参数化通道，或有转义测试 | 🔴 |
| SEC-2 | 路径穿越 | 文件读写限定在 workspace 内；`..`/绝对路径/软链有拒绝测试 | 🔴 |
| SEC-3 | 密钥 | 无硬编码密钥/token；`smoke.sh` 泄露初检通过；密钥只走环境变量/密钥服务 | 🔴 |
| SEC-4 | 沙箱分级 | 命令按只读/可写/高危分级，高危需审批且审计留痕（H2） | |
| SEC-5 | 依赖 | 无新增高危依赖；新增依赖有 ADR（含替代项与拒绝理由） | |
| SEC-6 | 错误信息 | 对外错误不带栈/路径/密钥；内部细节只进日志 | |

常见失败：`os.system(f"...{user_input}")`、`open(user_path)` 未校验。

---

## 3. Safety（安全运行/无害性）

目标：不毁数据、不杀错进程、不产生不可逆副作用；危险动作先干跑（对应 `AGENTS.md` §5 进程与数据条款）。

| 编号 | 检查点 | 通过标准 | 阻断 |
|---|---|---|---|
| SAF-1 | destructive 操作 | 删除/覆盖/迁移/kill 前有 `--dry-run` 或二次确认；文档写明回滚 | 🔴 |
| SAF-2 | 进程 | 不 kill 用户长驻进程；只清理自己起的进程（有 PID/会话归属证据） | 🔴 |
| SAF-3 | 用户文件 | 未跟踪且非本会话创建的文件不删不覆盖（`git status` 干净或仅预期文件） | 🔴 |
| SAF-4 | 生成器副作用 | 安装器/生成器跑后检查工作树，附带改动已回滚或已说明 | |
| SAF-5 | 默认值安全 | 危险 flag 默认关闭；批量操作默认小批量 + 显式 `--all` 才全量 | |

常见失败：`rm -rf` 变量为空、`git clean -fd` 误清用户文件。

---

## 4. Privacy（隐私）

目标：最小采集、用后即焚、可追溯；会话日志不成为泄露源（`HARNESS.md` H1）。

| 编号 | 检查点 | 通过标准 | 阻断 |
|---|---|---|---|
| PRI-1 | 最小采集 | 只读任务必需路径；无全盘扫描/`find /`/`ls -R /`（`AGENTS.md` §5） | 🔴 |
| PRI-2 | 脱敏 | 日志/交付/测试夹具中无真实密钥、token、个人路径（`$HOME` 外显需脱敏） | 🔴 |
| PRI-3 | 留存 | 会话 jsonl 有保留策略（目录约定 + TTL）；敏感会话可一键清理 | |
| PRI-4 | 出境 | 需外发数据时声明目的地 + 字段白名单；默认不出境 | |
| PRI-5 | 复用 | 测试/示例不用真实用户数据；用合成夹具并标注 | |

常见失败：把完整 session log（含 token）贴进交付说明、测试夹具带真邮箱。

---

## 5. Reliability（可靠性）

目标：契约稳定、回归可重复、边界无歧义（`ARCHITECTURE.md` 红线 1–3）。

| 编号 | 检查点 | 通过标准 | 阻断 |
|---|---|---|---|
| REL-1 | 契约来源 | 错误类型/返回值/默认值与 sibling 代码及现有测试一致；分歧有 ADR | 🔴 |
| REL-2 | 边界约定 | 成对边界（start/end 等）用同一 inclusive/exclusive 约定并有注释/ADR 依据 | 🔴 |
| REL-3 | 测试锁定 | 行为变更有测试锁定；现有测试失败视为需求，未改测试断言去迎合实现 | 🔴 |
| REL-4 | 可重复 | 同一输入多次运行结果一致；涉随机/时间用种子或注入时钟 | |
| REL-5 | 版本兼容 | 公共 API/数据形状变更走 ADR，注明迁移与回滚；旧字段保留一版 deprecation | |
| REL-6 | 可观测 | 关键路径有结构化日志（输入摘要/耗时/结果码），失败可定位到单次调用 | |

常见失败：改了返回 key 却只改调用方之一、边界 off-by-one、flaky 测试靠重跑过。
